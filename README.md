# PPT 自虐工厂

**冲顶级 PPT，粉碎 Token、时间和硬盘。欢迎带着资料来挑战。**

这是给 Codex 使用的三段 PPT 工作流。先把资料讲清楚，再把脚本变成整页图片，最后重建为原生可编辑 PPT。它适合愿意为画面效果、内容准确和可编辑性反复检查的人。

“粉碎机”是对资源消耗的自嘲。最终效果依赖材料、模型、字体、运行工具和人工审核。本项目公开真实检查结果，欢迎反馈失败案例。

> **当前版本：0.1.0-alpha.1，工作流测试版。** 包含三个技能、辅助脚本和离线测试。新公开包尚未完成真实生图到 PowerPoint 的端到端验证。二、三需要使用者已经获得合法使用权的 `@oai/artifact-tool`；仓库不分发该运行库。安装成功后仍要按[环境要求](docs/requirements.md)检查实际能力与授权。

## 你会得到什么

| 模块 | 技能 | 输入 | 交付 |
| --- | --- | --- | --- |
| 一：内容与脚本 | `$ppt-storyboard` | 用户提供的资料与要求 | 逐页脚本、讲稿、视觉要求、来源记录 |
| 二：图片 PPT | `$ppt-image-deck` | 已确认的逐页脚本 | 图片版 PPT、逐页图片、提示词与交接清单 |
| 三：可编辑重建 | `$ppt-editable-rebuild` | 图片 PPT、逐页图片或二的交接包 | 可编辑 PPT、素材记录、逐页检查与验收报告 |

```text
原始资料 ── 一：内容与脚本 ── 二：图片PPT ── 三：可编辑PPT
                              ↑                 ↑
                        已有脚本可从此开始   已有图片可从此开始
```

普通文字、表格、模块框和连接线在三中重建为原生对象。照片、界面和生成插画按批准范围保留为独立图片。整页生图不会自动产生所有透明素材或 SVG 图标；二没有这项承诺。

## 安装到 Codex

需要 Git 和 Python 3.10+。以下命令下载本仓库并安装三个技能，会在个人技能目录创建新文件夹。

```bash
git clone https://github.com/Daviddwt/ppt-self-torture-factory.git
cd ppt-self-torture-factory
python3 scripts/audit_public.py
python3 scripts/install.py
python3 scripts/install.py --apply
```

安装器先展示目标路径，带 `--apply` 才执行。默认目标是 `${CODEX_HOME}/skills`；未设置时用 `~/.codex/skills`。已有同名技能时整批停止，原文件保留。也可用 `--destination <技能目录>` 指定位置。每个已安装技能附带许可和第三方说明。安装器不会安装依赖、修改模型、写入账号或启动生产。

安装后在新的 Codex 对话中调用技能。如果客户端没有自动发现新技能，可明确提供对应 `SKILL.md` 的位置。支持插件目录导入的客户端也可以读取仓库中的 `plugin.json`；本次验证覆盖文件安装方式，客户端插件界面安装待实测。

先让 Codex 运行环境检查：

```bash
python3 scripts/preflight.py --stage all
```

这一步只读取基础环境，并列出需要在当前对话验证的能力。内置生图、子智能体和 PowerPoint 不能靠文件存在推断可用。

## 怎么开始

有原始资料时：

> 使用 $ppt-storyboard，根据我提供的资料准备一份 6 页演示脚本。先确认读者、要解决的问题和材料缺项，脚本经我确认后再交接给二。

有脚本时：

> 使用 $ppt-image-deck，读取已经确认的 script.json。先检查当前 Codex 的真实生图能力和 PPT 工具授权，完成一页样页后让我确认，再生成图片版 PPT。

有图片 PPT 时：

> 使用 $ppt-editable-rebuild，把这份图片 PPT 重建为可编辑 PPT。保留源图布局，先做代表样页，按七个独立角色和真实 PowerPoint 验收流程执行。

仓库附带[三页虚构脚本](skills/ppt-storyboard/examples/fictional-script.json)，用于理解格式与离线测试。它是练习输入，真实成片展示待后续验证后补充。

## 质量和成本怎么取舍

三保留七个独立角色：总调度、页面分析、元素拆解、素材处理、PPT 制作、视觉对比、独立验收。并发槽位不足时分阶段执行，每个角色仍需有真实身份和交付记录。

默认逐页评分至少 90 分，90—94 分列明差异。分数来自审核量表；文字、数字、关系、原生对象与实机验证还有独立要求。用户可以在任务开始时提高门槛。

建议先做 1 页样页，再以 3—5 页推进。事先约定最多返工轮数、时间和资源预算，达到上限即报告未解决问题。输出目录按批次复用，源文件和有效成果始终保留，清理需由使用者决定。

成本记录包含阶段耗时、返工次数、输出体积与能实际采集的 Token。无法采集的字段写“未采集”。共享账户额度变化不能精确归因于一个任务；本项目没有省 Token 或提速比例承诺。
