# 运行前确认实际能力

三个技能在 Codex 当前对话中执行。先读取已经接入的工具与演示文稿文档，再判断本次能做到哪一步。

| 阶段 | 必需条件 | 怎样确认 |
| --- | --- | --- |
| 一 | 读取用户批准的资料、生成文件 | 成功读取代表材料，输出并校验脚本 |
| 二 | 内置生图、查看生成结果、Node.js 20+、PPT 运行库 | 真实工具存在，图像保存成功；在授权范围内完成小型 PPT 能力检查 |
| 三 | 看图、真实子智能体、PPT 运行库、所需字体、PowerPoint | 独立角色可调度；候选实际保存并重读；最后执行实机编辑验证 |

Python 助手需要 Python 3.10+。具体脚本参数见各技能内说明。仓库没有外部生图 API 适配器，也不固定图像模型的商业名称；工具未返回模型标识时记录 `unknown`。

## 运行库与许可

二、三沿用 `@oai/artifact-tool` 路线。通过当前 Codex 的工作区依赖工具或演示文稿文档定位合法提供的运行库。运行库的具体版本、入口和 API 以接收环境为准。

仓库不包含该库或其内部文档，也不从公共包源自动安装同名库。发现本地文件只说明文件存在。请先核实该版本的许可是否覆盖本次用途；许可不明或不允许目标用途时停止二、三的相应步骤。

`preflight.py` 不导入运行库、不发送网络请求。它列出基本环境结果和人工核实项，不能签发完整生产许可。技能中的能力检查需要在允许的用途内执行，并保留实际工具返回结果。

## PowerPoint 验证

三的最终验收需要 Microsoft PowerPoint。没有 PowerPoint 或无法操作时，可以保留中间稿及检查结果，交付状态写“实机验证待完成”。使用者后续可提供真实操作记录，再由验收角色复核。

打开文件前使用稳定的本地审核目录。第一次出现 Office 文件访问授权时，交由用户完成授权，避免后台循环重试。验收记录绑定候选文件的 SHA256；候选变化后重新检查受影响部分。

## 资源与停止条件

开始前约定页数、样页、字体、每页返工上限和预算。用户尚未指定时，建议先做一页样页，每页最多两轮修复；获得任务范围确认后再继续批量生产。

缺工具、缺授权、资料冲突、预算到达或关键问题连续两轮未解决时，记录当前位置、已产生文件与可选下一步。更换引擎或改用截图覆盖会改变路线，需要用户确认。
