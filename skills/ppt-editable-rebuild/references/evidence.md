# 用当前文件与真实操作完成验收

## 逐页评分并记录差异

| 维度 | 满分 | 检查内容 |
| --- | ---: | --- |
| 布局还原 | 30 | 画布、区域、对齐、间距和视觉层级。 |
| 元素完整 | 25 | 标题、正文、表格、图例、图片、关系和页脚。 |
| 字体颜色 | 20 | 字体、字重、字号、换行、色彩和线条。 |
| 文字语义 | 15 | 文字、数字、单位、方向和关系含义。 |
| 可编辑视觉损伤 | 10 | 原生对象重建后的形状、布局和阅读效果。 |

每页至少 90 分。90 至 94 分须列出具体差异及影响，最终验收员再判断是否满足硬性条件。评分表达审核判断，单位为分。它不表示像素一致率。

文字数字错误、关键元素缺失、箭头反向、违规大图、普通结构不可编辑、缺少独立审查和实机失败均阻断交付。任何分数都无法豁免这些问题。视觉对比员应打开完整源图和从当前 PPTX 重新导入得到的渲染图，局部放大用于核对细节。

## 报告绑定输入、候选和执行者

每份视觉报告和最终验收报告都包含下列字段。以下是填写要求，不是已经完成的执行记录。

| 字段 | 要求 |
| --- | --- |
| `input_files` | 源文件及各自 SHA-256；源图、文字脚本和已确认素材分别列出。 |
| `candidate` | 当前 PPTX 文件名、SHA-256、页数与页码映射。 |
| `executor` | 当前真实执行者标识、角色、开始时间和结束时间。 |
| `evidence` | 实际查看的源页、渲染图、截图及其哈希，附目标页码。 |
| `page_reviews` | 各维度得分、合计、差异位置、影响、硬性条件和修复状态。 |
| `native_objects` | 普通文本、表格、形状和连接线的结构记录与实机点选结果。 |
| `powerpoint` | 文件身份、打开结果、编辑对象、保存关闭重开结果和截图。 |
| `decision` | 通过、返修或待确认；列明未解决问题。 |

每次修改候选后生成新 SHA-256。前一份报告保留，但通过状态不迁移到新文件。复制到交付目录后核对哈希；如果另存导致内容变化，按新文件重新验收。

## 验证实机编辑与保存

使用稳定工作目录保存当前候选和单独的验证副本。macOS 先完成 Office 文件访问授权，Windows 使用稳定的本地工作目录。只有当前环境提供并支持的打开工具才可调用。禁止无人值守地反复打开临时逐页副本。

1. 记录候选哈希、PowerPoint 版本和验证副本的初始哈希。
2. 在真实 PowerPoint 打开当前候选，核对文件身份、全部页面和修复提示。
3. 检查主要原生对象能否独立选中，查看字体、遮挡、溢出和图层关系。
4. 在验证副本中修改原有文字；任务含表格时修改原有表格单元格。仅新增文本框不算原对象编辑验证。
5. 保存、关闭、重开验证副本，确认修改保留且布局正常。
6. 记录验证副本的最终哈希、编辑前后截图、具体对象和实际观察。

每类主要原生对象都要有检查证据。表格行高列宽、字体替换和连接线位置在保存重开后复查。截图需要确认当前文件和目标页。人工执行的步骤标为人工验证。

PowerPoint 不可用、文件访问授权未完成或没有实际操作证据时，实机状态保持待验证。结构检查、图片渲染和执行者声明均不能替代该步骤。最终交付使用未被测试改字污染、且哈希已验收的候选文件。

## 结构助手的能力与限制

`scripts/ooxml_check.py` 读取 PPTX ZIP 内容但不解压。运行环境为 Python 3.10 或更新版本，仅依赖标准库。它检查危险路径、重复条目、大小限制、XML 可解析性、关系目标、演示文稿页面顺序和基础对象统计。默认拒绝加密条目、DTD、实体声明和不支持的压缩算法。它只支持常用的 Transitional OOXML；其他格式明确报告不支持。带百分号转义的 ZIP 条目路径按不支持处理，避免路径歧义。

图片面积统计仅覆盖幻灯片顶层、未旋转的 `p:pic` 矩形。它按矩形在画布内的并集计算，避免把重叠图片重复相加。分组、旋转、继承背景、图片填充、遮挡、透明像素和实际裁切语义需要另行检查。报告中的 `known_picture_rect_union_ratio` 只是已知矩形的比例。

尺寸检查按对象类型执行。连接线和明确标为 `line` 的形状允许单轴为零，两个方向均须非负且至少一个方向有长度。普通形状、图片和图形框中的表格等对象，其显式宽高均须大于零。页面根组的默认变换不参与这项检查。

普通分组只检查显式 `ext`、`chExt` 是非负整数，零尺寸保持待审查。组内对象按自身类型检查。助手不计算分组缩放后的几何关系，也不检查继承尺寸；报告用 `unmeasured_groups` 标记相关分组。

图片覆盖率高时需要结合源图审查；覆盖率低或对象数量多时，可编辑性仍为未评估。脚本不读取文字的业务含义，也不判断完整可编辑。视觉评分、独立角色核对和 PowerPoint 操作均由其他步骤完成。`structural_status: pass` 只表示本助手列出的结构检查通过。

```sh
python3 scripts/ooxml_check.py candidate.pptx \
  --source source.pdf --source approved-copy.md \
  --expected-sha256 CURRENT_CANDIDATE_SHA256 \
  --json-out reports/structure.json
```

`CURRENT_CANDIDATE_SHA256` 需替换为当前候选的 64 位十六进制哈希。`--source` 可重复，用于记录输入哈希。未提供来源时报告缺少来源绑定。输出报告使用新文件名，助手拒绝覆盖已有报告。候选文件和来源文件均只读；报告不会创建通过的独立审核或实机记录。

退出码 `0` 表示列出的结构检查通过，仍可能存在待人工审查提示。退出码 `1` 表示结构失败或读取失败，退出码 `2` 表示命令参数或报告写入失败。压缩包上限为 256 MiB，总解压大小上限为 512 MiB。单条目上限为 64 MiB，条目数量上限为 20,000。超过限制时停止检查，保持未验收状态。

单元测试只使用内存构造的最小 OOXML 测试文件。它们验证路径防护、关系检查、哈希绑定、矩形计算和结论边界。真实演示文稿的外观和 PowerPoint 兼容性需要另行验收。
