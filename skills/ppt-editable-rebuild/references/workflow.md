# 按源图完成原生重建

## 先冻结输入和依赖

每次任务使用独立目录，原稿只读保留。目录分工如下：

| 目录 | 内容 |
| --- | --- |
| `source/` | 原始资料。 |
| `specs/` | 页面和对象规格。 |
| `assets/` | 素材与清单。 |
| `candidate/` | 当前候选 PPTX。 |
| `previews/` | 从实际 PPTX 生成的预览。 |
| `reports/` | 检查与验收记录。 |
| `final/` | 已完成验收的交付文件。 |

输入记录包括文件名、SHA-256、页数、源图尺寸、目标页码、权威文字来源、字体与引擎版本。

运行库来自使用者已获授权的环境。本包不分发第三方私有运行库，不自动安装依赖，也不包含运行库内部代码。依赖工具返回的可用路径和当前公开 API 文档是能力验证依据。许可证未知或不允许目标用途时，停止该生产步骤，由使用者确认授权。导入、创建、保存、重新导入和渲染应分别取得结果。能力测试通过后再开始用户材料制作。

图片查看、真实智能体分派和 PowerPoint 分别验证。任何一项缺失，都记录具体阻塞与下一步负责人。依赖缺失时停止依赖该能力的步骤。禁止静默换成其他制作引擎、整页截图覆盖、模板套版或伪造执行记录。

## 核对模块二交接包

模块二交接包使用以下结构：

| 文件或字段 | 内容要求 |
| --- | --- |
| `script.json`、`deck.pptx`、`manifest.json` | 分别为文案脚本、图片型 PPT 和交接清单。 |
| `build-manifest.json`、`HANDOFF.md` | 分别为组装记录和交接说明。 |
| `prompts/<id>.md` | 该页的实际提示词。 |
| `assets/<id>.png` | 该页的整页图片。 |
| `receipts/<id>.json` | 该页的生成回执。 |
| `manifest.schema_version` | 固定为 `1.0`。 |
| `manifest.kind` | 固定为 `image_ppt_to_editable`。 |
| `script_path`、`script_sha256` | 脚本路径及 SHA-256。 |
| `deck_path`、`deck_sha256` | 图片型 PPT 路径及 SHA-256。 |
| `build_manifest_path`、`build_manifest_sha256` | 组装记录路径及 SHA-256。 |
| `slides[]` 的内容字段 | 保留 `id`、`title`、`key_message`、`on_slide_text`、`speaker_notes` 和 `source_refs`。 |
| `prompt_path`、`prompt_sha256` | 该页提示词路径及 SHA-256。 |
| `image_path`、`image_sha256` | 该页图片路径及 SHA-256。 |
| `receipt_path`、`receipt_sha256` | 该页生成回执路径及 SHA-256。 |
| `generation` | 实际生成来源记录。 |
| `independent_assets` | 初始为空，表示本阶段没有输出独立素材。 |
| `qa` | 实际检查状态，待执行项目保持 `pending`。 |

接收方先核对路径安全与全部文件哈希。所有引用路径均相对于交接根目录；拒绝绝对路径、目录越界和指向根目录外的符号链接。脚本、源 PPT、组装记录和逐页文件都要存在，其 SHA-256 与对应清单字段一致。图片哈希使用 `image_sha256` 字段。

哈希通过后读取内容，核对清单与脚本的页数、页序、唯一页面标识和文案。再核对组装记录中的脚本哈希、页序和逐页文件哈希。打开每张整页图，核对页面内容、文案、顺序与图片型 `deck.pptx`。`script.json` 是文字依据，PNG 是视觉参考，提示词用于核对生成要求。

回执用于核对生成工具、实际模型信息和对应页面，真实性须与实际工具结果核对。`model_id` 为 `unknown` 时如实保留，不推断模型。缺图、哈希错误、页码不符或关键来源字段冲突时，停在接收检查阶段并列出问题。交接图是重建的源图，整页插入新 PPT 仍处于图片稿状态。空的 `independent_assets` 不提供独立图标或插画文件，需在素材步骤单独取得。

交接包检查完成后，分别记录清单、脚本、图片、回执和源 PPTX 的哈希。`ooxml_check.py` 只检查 PPTX 结构，交接包核对由接收角色按本节执行并留存证据。用户已有图片 PPT、PDF 或逐页图可独立进入。接收角色建立页码映射、权威文字和源图哈希，再进入七角色流程。

## 用七个执行者完成七种职责

总调度可由主智能体担任，其余六个角色各分派一个独立智能体。实际标识由 Codex 执行环境提供，名称和角色标签只用于阅读。记录执行者接收的文件、哈希、开始时间、结束时间和实际产出。人员手工补验要标注为人工验证。

槽位不足时依次完成分析、拆解、素材、制作、视觉审核和最终验收。执行者完成后释放并发槽位，保留原始执行证据。重用同一执行者处理本角色的返修可以继续；同一执行者兼任其他独立角色不符合本技能。

视觉对比员只报告问题和评分。制作员根据问题单修改当前候选。最终验收员独立读取当前候选和全部报告，核对失败页是否关闭。由制作员代写审核结论、复制历史分数或将角色名称当作独立执行证据，均阻断验收。

## 逐个登记页面对象

页面规格记录页面尺寸和坐标单位。每个元素登记 `element_id`、源页、文字或语义、位置和尺寸。样式记录颜色、字体、线宽和层级。制作要求记录目标对象类型、素材引用和不确定项。连接线记录起点、终点和箭头方向。

源图与权威文字发生冲突时暂停该页。文字缺失、低分辨率导致数字不清、关系无法辨认时，也先补齐材料。页面规格完整后，制作员按实际 API 创建原生文字、形状、表格和连接线。对象位置采用页面坐标，字号和行距在实际字体环境中校准。

保存候选 PPTX 后重新导入并渲染，渲染图绑定候选文件哈希。内存中的预览只用于制作过程。合并文件后重新核对页码、顺序、数量和对象，生成新候选哈希并复核全稿。

## 素材按用途和来源登记

| 素材 | 使用规则 |
| --- | --- |
| 普通图标 | 优先检索真实图标库，导出独立文件，记录库名、来源地址、许可、版本和哈希。 |
| 照片、界面、插画 | 优先复用原文件，保持比例、裁切和透明边缘。 |
| 只能从源页提取的图像 | 记录源页哈希与裁切坐标，标为源图提取。 |
| 普通表格、流程、文字 | 重建为原生对象。 |
| 缺失或语义不符的素材 | 列出缺项，等待补充或具体替代授权。 |

素材清单用 `required` 表示必须使用，用 `optional` 表示允许使用。`forbidden_for_source_fidelity` 表示为保持源图禁止使用。每项附 `asset_id`、目标页、位置、比例、来源文件、实际使用文件和 SHA-256。素材有许可限制时保留许可说明。

透明 PNG 检查真实透明通道。SVG 检查是否内嵌位图，内嵌位图的文件按混合素材登记。提示词出现某个库名，不能证明已经取得该库的图标。品牌标记、勾选符号和方向图标需要语义一致。

单张图片占页面面积不超过 5% 时仍登记来源；超过 5% 时说明保留原因；超过 20% 时确认具体源图例外；超过 40% 时通常阻断，真实照片、界面、地图或三维视图页可按已确认例外审查。相关授权已有记录时沿用该记录。相邻图片的并集和语义区域一并检查，拆片不改变原生性要求。

## 样页通过后分批推进

选择包含典型表格、流程、图片和文字密度的代表样页。样页通过结构、独立视觉与实机验证，并取得用户认可后，再按 3 至 5 页扩展。每批记录页面范围、候选哈希和仍待处理的问题。

返修同时检查修改区域和未修改区域。素材、字体或引擎版本变化时，重新评估受影响页面。最终合并文件重新取得完整预览与当前文件的验收记录，历史报告保留为过程证据。
