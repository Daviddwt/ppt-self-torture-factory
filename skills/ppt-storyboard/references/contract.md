# 脚本与下游交接约定

模块一输出 `script.json`，模块二按相同字段读取。`script.md` 是便于人工阅读的对应稿，两份文件的标题、上屏文字和讲稿应一致。

## 基础字段保持稳定

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 字符串 | 固定为 `1.0`。 |
| `title` | 非空字符串 | 整套演示的名称。 |
| `canvas.width`、`canvas.height` | 整数 | 每维为 1 至 16384 像素，例如 `1920` × `1080`。实际生图尺寸由下游检查。 |
| `slides` | 数组 | 包含 1 至 500 页，按演示顺序排列。 |
| `slides[].id` | 非空字符串 | 全稿唯一的页面编号，忽略大小写判重；格式规则见下文。 |
| `slides[].title` | 非空字符串 | 页面标题。 |
| `slides[].key_message` | 非空字符串 | 这一页希望读者记住的结论。 |
| `slides[].on_slide_text` | 字符串数组 | 标题以外的上屏文字；数组可以为空，每项字符串须有文字。 |
| `slides[].speaker_notes` | 字符串 | 讲稿；确实无需补充时可为空。 |
| `slides[].image_prompt` | 非空字符串 | 自包含的生图提示词，保持已确认的文字和关系。 |
| `slides[].source_refs` | 字符串数组 | 对应来源目录中的编号；数组可以为空，每项字符串须有文字。 |

页面编号使用 1 至 64 个英文字母、数字、连字符或下划线，首字符为字母或数字。规则为 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`，建议使用 `p01`、`p02`。编号会用于下游文件名，因此不含斜线、点号或其他路径字符。

唯一性检查忽略大小写：`p01` 和 `P01` 视为重复，避免大小写不敏感的文件系统覆盖页面。

非空字符串去掉首尾空白后仍须有内容。`on_slide_text` 和 `source_refs` 接受空数组，拒绝空字符串及仅含空白的数组元素。

各层允许额外字段，消费者只读取自己认识的字段，转存时保留其余内容。基础校验不强制额外字段，也不会判断论证是否充分。

## 来源和审阅记录便于人工核对

建议在根对象增加 `sources` 数组，每条记录使用以下字段：

- `id`：与页面 `source_refs` 对应的唯一编号。
- `title`：资料名称或用户说明的主题。
- `locator`：文档页码、章节、表格位置或对话记录位置。
- `version`：日期、版本或其他可识别的来源状态。
- `summary`：实际采用的内容，保留影响结论的限定条件。
- `kind`：例如 `user_document`、`user_statement`、`public_reference` 或 `fictional_example`。

来源名称和摘录按用户允许的范围填写。交接资料使用输出目录内的相对路径或获准引用的公开链接，避免写入账号信息和本机绝对路径。

建议用 `review.status` 记录 `pending` 或 `approved`。`approved` 只记录真实的用户确认，并附确认记录位置及对应版本。虚构示例使用 `example_only`。校验助手不会把该字段当作真实授权，也不会自动批准内容。

## 视觉安排可以扩展

关系复杂时，在页面增加 `diagram_spec`：

```json
{
  "nodes": [{"id": "a", "label": "登记"}, {"id": "b", "label": "交接"}],
  "edges": [{"from": "a", "to": "b", "label": "登记完成后", "kind": "sequence"}]
}
```

每条连线说明含义，例如顺序、并行、反馈、数据传递或异常分支。同步更新文字、连线和 `image_prompt`，确保它们表达同一流程。

需要真实素材时可增加 `assets` 数组，记录 `id`、`path`、`role` 和 `permission`。其中 `path` 相对 `script.json` 所在目录。交接时检查文件存在、可读取，并说明哪些页面使用它。

## 本阶段完成到哪里

提交文件时说明已读取的资料、检查结果、审核状态、输出位置和待确认项。只有用户审核了对应版本，才交给下一阶段执行。结构校验、内容审核、生成图片和打开 PPT 是四项不同的检查结果。
